共享海面：UE5 落地要点

对应工程 GTL-Net-SharedOcean（UE 5.8，C++，不改引擎）。按数据流顺序列出《盗贼之海》式多人海面的每一步做法：确定性 FFT 海面、网络时钟、服务器权威的船、快照压缩与客户端呈现，附关键常数、坑点和移植清单，可以直接对照源码搬进自己的项目。原理、业界方案对比与推断依据见 Research.html。

1. 总览

核心思路只有一句：海面不同步，只同步算海面的输入。海面是“种子、海况参数、时间”的纯函数，每台机器各自计算；网络上只传海况（几十字节，变化时才发）和让各端时间对齐的时钟样本。船是服务器上的刚体，服务器读自己的海面算浮力，把结果作为快照发给客户端；客户端再决定怎样把这条船放到自己算出的海面上。

模块对应关系：OceanFFT（纯 C++ 的 FFT 级联，不依赖 UObject）、OceanManager（每台机器本地生成，不复制）、SONetClock（客户端控制器上的组件）、SOShip（复制的 Actor，自定义快照序列化）、OceanSurface + 材质（渲染）、SharedOceanShaders 模块（画面波段的 GPU 路径）。

每个级联只保留落在自己波长带里的波矢（InBand），带与带不重叠，所以叠加后不会重复计能量。图块边长取非整数比（768 / 192 / 48 / 11.7），避免各级的平铺周期对齐。分界选在 16 m：比船长（约 21 m）短得多的波对船体整体运动几乎没有影响，可以只留给画面。

频谱与振幅

Phillips(k) = exp(-1/(k·L)²) / k⁴ · (k̂·ŵ)² · against · exp(-k²·0.05²) · Δk²
             L = V²/g；逆风分量 against = 0.07；0.05 m 以下的毛细波被压掉
Swell(k)    = exp(-((k - ks)/(0.12·ks))²) · max(k̂·d̂, 0)²⁴      // 窄带长涌浪，美术可调
振幅定标：把 G0..V3 四个级联的 Phillips 总和 Σ 定标到目标有效波高
             VarianceScale = (Hs/4)² / Σ
每个模态：  Amp = sqrt(Var · 0.25)   // h̃ 同时用 h0(k) 和 conj(h0(-k))，每个抽样只分到一半方差
海况风速有效波高 Hs涌浪振幅 / 波长choppiness λ
平静6 m/s0.7 m0.6 m / 90 m0.9
普通11 m/s2.0 m1.8 m / 110 m1.15
风暴18 m/s4.8 m5.0 m / 135 m1.3

三档的振幅表在开局和涌浪倍率变化时一次算好（RebuildTables），每帧只按过渡进度在两张表之间插值。过渡进度 = smoothstep((共享时间 − ChangeTime) / 8 s)，因为 ChangeTime 是复制下来的服务器时间，所有机器在同一时刻走到同一个混合比例。“夸张巨浪”主要靠涌浪项：它是一个独立的美术参数，不受 Phillips 谱高度的物理约束，演示里用 , . 调倍率。

确定性的三个条件

  1. 随机数固定：每个级联的高斯抽样表 Xi 在初始化时用 FRandomStream((Seed·31 + 级联种子) · 2654435761) 按固定顺序生成一次，之后只读。种子随海况复制。
  2. 色散量化：ω = max(1, floor(√(g|k|) / ω₀)) · ω₀，ω₀ = 2π / 512 s。每个分量的周期都整除 512 s，整片海每 512 s 精确重复，时间可以取模，float 精度问题不会随运行时长累积。
  3. 相位用 double：Ph = fmod(ω · T, 2π) 在 double 下计算后再转 float 求 cos / sin。T 是取模后的海浪时间（0–512 s）。

做到这三点后，海面在各端的差异只来自时间误差和浮点运算顺序（ParallelFor 的分块不影响结果，因为每个元素的计算互相独立）。

一次求值：四个复数 FFT 输出八个实数场

H  = h0(k)·e^{iωt} + conj(h0(-k))·e^{-iωt}
F1 = H + i·Dx          → 逆 FFT 后 实部 = 高度 h，     虚部 = 水平位移 Dx
F2 = Dy + i·(i·kx·H)   →           实部 = Dy，         虚部 = ∂h/∂x
F3 = i·ky·H + i·(−kx·nx·H)  →      实部 = ∂h/∂y，      虚部 = ∂Dx/∂x
F4 = −ky·ny·H + i·(−kx·ny·H) →     实部 = ∂Dy/∂y，     虚部 = ∂Dx/∂y
J  = (1 + λ·Dxx)(1 + λ·Dyy) − (λ·Dxy)²    // 雅可比，< 阈值处生成泡沫

利用“实数场的频谱共轭对称”，把两个实数场装进一个复数 FFT 的实部和虚部，四次逆 FFT 得到高度、两向位移、两向斜率和雅可比所需的三个导数。服务器（没有画面）只需要 F1、F2（bFull = false），客户端的玩法波段和画面波段都算全套。泡沫是时间积分量（阈值 0.72、增益 3、衰减 2.6 s，V3 为 0.8 s），只用于画面，不属于共享状态。

注意：泡沫、法线这类纯画面量可以各端不同；任何会影响判定的量（高度、位移）都必须只来自“种子、参数、时间”。在海面上加任何带状态的东西之前，先确认它不进玩法波段。

4. 网络时钟

海面一致的前提是各端的“现在”一致。USONetClock 是一个简化的 NTP：

客户端：ServerClockPing(t1 = FPlatformTime::Seconds())
服务器：ClientClockPong(t1, Ts = 服务器 World 时间)
客户端收到时 now：
    RTT    = now − t1                       // ≤ 0.5 ms 的样本丢弃
    Offset = Ts + RTT/2 − now
    窗口保留最近 24 个样本，取 RTT 最小的那个作为 TargetOffset
每帧：
    |Target − Smoothed| > 1 s → 直接跳到 Target（首次锁定或长时间卡顿）
    否则 Smoothed 向 Target 移动，每秒最多 0.05 s（即海浪快慢最多变化 5%）
服务器时间估计 = now + Smoothed
  • 为什么取最短往返的样本：RTT/2 假设上下行延迟相等，往返越短，不对称的余地越小。抖动大的网络里，平均值会被排队延迟拉偏，最小值不会。
  • 为什么限速修正：时间一跳，整片海就会瞬移；限速后海浪只是略快或略慢，肉眼看不出。时间也永远不会倒退。
  • 用实时时钟测往返：FPlatformTime::Seconds() 单调且不按帧量化。用 World 时间测 RTT 会被帧时间量化，60 fps 下误差就是十几毫秒。

演示用 F3 在三种来源之间切换对照：网络时钟、引擎默认的 GetServerWorldTimeSeconds()、客户端自己的 World 时间。自测在模拟 200 ms 延迟时，网络时钟的误差仍在 0.1 ms 以内；本地时钟会让两端的海浪错开十几秒（客户端进入地图的时间差），吃水偏差从约 10 cm 变成约 35 cm。

5. 高度查询

FFT 海面带水平位移：网格点 x₀ 被移到 x₀ + D(x₀)。要问“世界坐标 P 处的水面多高”，需要先反解 P 是从哪个静止点移过来的：

rest = P
重复 N 次： rest = P − D_xy(rest)     // 不动点迭代，λ < 1.3 时几次就收敛
height(P) = D_z(rest)

船的浮力用 4 次迭代，吃水统计和宝箱用 3 次，法线（±1.5 m 中心差分）用 2 次。D 是 G0 + G1 在 CPU 上的双线性、环绕采样，风暴区内按 StormWeight 与 S0 + S1 混合。服务器开关里的“高度查询”可以改成 0 次迭代（直接取 D_z(P)），浪越陡、λ 越大，船和浪的错位越明显，这是常见的“船浮在浪的侧面”问题的来源。

6. 船：服务器权威模拟

固定步长

服务器每帧把真实时间累加进 Accumulator，按物理频率（默认 60 Hz，可切 30 / 10）走整数步，单帧最多 12 步；渲染位置在上一步和当前步之间按余量插值。快照的 ServerTime 是物理步的时间戳，不是帧时间，客户端据此插值。

浮力：探针受力（默认）

N 个探针，位于原点下方 1.5 m（静止吃水 RestDraft = 1.5 m）
K = g / (N · RestDraft)                      // 质量归一化的刚度：静止时总浮力正好等于重力
C = 2 · 0.55 · sqrt(g / RestDraft) / N       // 阻尼比 0.55
每个探针：depth = height(Pxy) − Pz
          Fz = max(K · min(depth, 2.6) − C · vz, −0.3K)   // depth ≤ 0 时不受力
          力矩的作用点取探针的 (x, y)，高度改为原点上方 0.6 m（稳心）
角加速度 = 力矩 / 归一化惯量 (4, 35, 38) m²（横摇、纵摇、偏航）
另加压载扶正 1.6 · (up × Z) 和横纵摇阻尼 0.45
坑：如果力矩按探针真实位置（水线以下）计算，船体倾斜时浮力作用点在重心下方，等于一个倒立摆，单探针或双探针时会直接倾覆。把作用点抬到稳心高度后，倾斜时浮力产生的是扶正力矩。

浮力：平面拟合 + 弹簧（《Atlas》式）

在船的偏航坐标系下取 N（至少 4）个点的水面高度，用最小二乘拟合平面 z = a·x + b·y + c（3×3 正规方程，克莱姆法则求解），以平面推出目标高度与目标法线，再用弹簧追随：竖直刚度 6.5、阻尼 2·0.6·2.55，角刚度 6.0、角阻尼 3.2。它在低物理频率（10 Hz）下比探针稳定得多，代价是丢掉了局部浪形的细节（船头扎进浪里这类表现）。

帆、舵与阻力

阻力在船体坐标系下分轴计算（纵向小、横向大），乘以湿探针比例；帆力沿船头方向，效率 = 0.15 + 0.85 × 顺风程度；舵产生的偏航角加速度与纵向速度成正比。这些参数只为手感服务，换成自己的航行模型时整段替换即可，网络部分不受影响。

8. 客户端呈现

位置用两端快照的速度做三次 Hermite 插值（比线性插值少了每 33 ms 一次的折角），姿态用 Slerp。难点在于：插值出来的船处在 100 ms 之前，而本地海面算的是“现在”，两者对不上时船会在浪里上下错位。演示提供三种呈现方式（F4）：

方式做法两端吃水差（自测）代价
整体快照插值整个姿态来自快照，海面画“现在”约 14 cm浪越快、延迟越大，错位越明显
海面同步回退整个姿态来自快照，本机海面也按同样的延迟时间计算和绘制（SetPresentationDelay）约 3–4 cm本机所有东西都看到 100 ms 前的海，和本地预测的物体（自己发射的炮弹）会有时间差
水平插值 + 竖直重建x、y、偏航来自快照；升沉、纵摇、横摇由本机按本地海面跑一个只算竖直方向的浮力模拟（每帧最多 4 个 60 Hz 子步），高度以每秒 35% 的速度向快照收敛，偏差超过 3 m 直接对齐约 9 cm升沉和摇摆不再与服务器逐帧一致，只在统计上一致；判定仍以服务器为准

选择建议：船上有玩家、需要“船贴着浪走”的观感时用竖直重建；需要和服务器姿态精确一致的场合（录像回放、观战）用海面回退；整体插值只适合远处的船。三者共用同一份快照，可以按距离混用。

9. 甲板与漂浮物

  • 甲板上的角色：船的根组件就是甲板碰撞盒（BlockAll、可移动）。角色用 CharacterMovement 的基座移动（movement base），bIgnoreBaseRotation = false，船每帧在 TG_PrePhysics 里摆好姿态，角色随基座一起移动和旋转。引擎的基座移动复制会把角色位置换算成相对基座的坐标发送，所以客户端上船怎么呈现，甲板上的人就跟到哪里。舷墙是几个额外的碰撞盒。
  • 掌舵：客户端只发输入（ServerHelmInput，舵角和升降帆增量，Unreliable），服务器写入船的控制量，再随快照复制回来驱动舵轮和帆的外观。
  • 漂浮物：宝箱只复制水平位置（2 Hz），高度和倾斜在每台机器上用本地海面的 HeightCm 与 NormalAt 计算。这类不影响判定的小物件完全不需要物理同步，带宽可以忽略。

10. 海面渲染

以相机为中心的几何 clipmap

9 层，每层 128 × 128 格，第 0 层格宽 50 cm，每层翻倍（第 8 层 128 m）。每层中心按“两倍格宽”吸附到相机位置，保证顶点落在下一层的格点上。第 1 层起挖掉中心 (128/4 − 1) 格的方洞，洞比内层小两格，重叠部分在材质里按内层矩形 InnerRect 丢弃。最外面是一圈平面裙边，一直延伸到 60 km。网格加了两个不引用的顶点（±30 m）撑大包围盒，避免位移后的浪被视锥剔除。

材质

// 顶点着色（WPO）：外圈 16 格内逐步把奇数格点并到偶数格点上，与外层无缝衔接
m    = saturate((dinf − (hc − 16)) / 14)
rest = (OBJ.xy + (g − odd·m)·CellSize) · 0.01        // 静止位置，米
w    = saturate(2 − 4·s / λmin)                       // 格宽 s 超过最短波长的 1/4 时淡出该级联
d    = lerp(G0+G1, S0+S1, 风暴权重) + V2 + V3          // 各自乘 w
// 像素着色：同样按静止位置采样斜率与位移，s 换成像素覆盖范围

按格宽淡出级联是抗混叠的关键：远处网格稀疏，如果仍叠加 3 m 的小浪，顶点采样会产生闪烁。颜色在深水色与次表面色之间按浪峰遮罩插值（Rare 在 SIGGRAPH 2018 公开的做法），泡沫取各级雅可比泡沫的最大值，再与合成的压缩量阈值合并，并用最细一级的高度打散成块状。

画面波段的 GPU 路径

V2、V3 默认在 GPU 上计算，三个 RDG 计算通道写入和 CPU 路径完全相同格式的纹理，可以在实验台随时切换对照：

  1. Spectrum（8×8 线程组）：读 H0 纹理（h0(k) 与 conj(h0(−k)) 打包成一个 float4），推进相位，写出 F1–F4 两张 RGBA32F。
  2. 逆 FFT：每条线一个线程组（64 或 128 线程，排列组合编译两份），在组共享内存里做基 2 蝶形，先行后列。
  3. Finalize：算雅可比、累积泡沫，写位移和导数纹理。
坑：在 UAV 上原地读写 RGBA32F（typed UAV load）不是所有平台都支持，D3D11 级别的硬件会编译失败。改为两组纹理来回交换：行变换 A、B → C、D，列变换 C、D → A、B，每一遍只读 SRV、只写 UAV。

着色器模块 SharedOceanShaders 的加载阶段必须是 PostConfigInit，并在 StartupModule 里用 AddShaderSourceDirectoryMapping("/SharedOcean", 工程/Shaders) 注册虚拟路径，否则全局着色器不会被编译。H0 只在振幅表变化（海况过渡中、涌浪倍率改变）时重新上传。

11. 测量与自测

RTX 3060 级显卡上，1600 × 900 窗口约 9 ms 一帧；海面 CPU 耗时约 1.4 ms（画面波段在 GPU 上），全部走 CPU 时约 2.3 ms。服务器只算玩法波段（G0、G1，以及风暴开启时的 S0、S1），不需要显卡。

powershell -File Tools/iterate.ps1 -Net 编译后离屏运行两组自测，全部通过注入的键鼠事件完成：

  • 主机 12 项：甲板行走、鼠标环视、掌舵、航速、转向、风暴有效波高、平面拟合稳定、10 Hz 物理、单探针不倾覆、GPU 画面波段、离舵、帧时间。
  • 主机 + 客户端 6 项：快照带宽与位数、时钟同步、三种时钟来源下的两端吃水差、模拟 200 ms 延迟下的时钟误差、三种呈现方式下的吃水差、客户端在航行的船上行走。

“两端吃水差”是这套系统最有用的单一指标：客户端用本地海面算出的船体平均吃水，减去服务器在同一服务器时刻的吃水（随快照下发）。它同时反映时钟误差、海面实现差异和呈现方式的好坏，接近 0 表示两端看到船以同样的方式坐在海上。

12. 坑点清单

  • 海面里混进状态：任何积分量（泡沫、波浪的“记忆”、交互涟漪）一旦进了物理查询，各端就会发散。玩法波段只能是纯函数。
  • 时间用 float：float 秒在运行几小时后只剩毫秒级精度，相位会抖。用量化色散让海面有限周期循环，相位在 double 下算。
  • 用 World 时间测往返：被帧时间量化，误差是半帧到一帧。测量用 FPlatformTime，海面求值用估计的服务器时间。
  • 高度查询不反解位移：λ 较大时直接读 D_z(P) 会让船浮在浪的侧面，误差可达半米以上。
  • 浮力力矩作用在探针处：少探针时等于倒立摆，船会翻。作用点抬到稳心。
  • 同时复制移动：自定义快照的船必须关闭 ReplicateMovement，否则引擎的移动复制会和自己的插值互相覆盖。
  • 插值延迟太小：小于“快照间隔 + 抖动”时缓冲被追空，船会周期性停顿。外推只做 0.2 s，超时宁可停住也不要瞬移。
  • GPU FFT 原地读写 UAV：typed UAV load 在部分硬件上不支持，用 SRV / UAV 交换。
  • 同一台机器双开：监听服务器默认占用 7777 端口，已开着的主机会让第二个主机自动换到 7778，客户端就可能连到旧主机；连接失败时客户端会退回单机地图，看起来像“第二个主机”。双开脚本应使用专用端口，并在客户端检测“没有成为客户端”时提示并重试。-WinX / -WinY 在这里不生效，两个窗口会叠在屏幕中央，需要在运行时用 SWindow::ReshapeWindow 摆放。
  • F1–F12 被引擎占用：开发版的调试执行绑定会把 F1–F5 映射成视图模式，在 DefaultInput.ini 里写 !DebugExecBindings=ClearArray。

13. 移植清单

  1. 拷贝 OceanFFT.h/.cpp（纯 C++），按自己的船长和视距调整级联表：玩法波段的下限取船长的 0.5–0.8 倍。
  2. 拷贝 OceanManager：每台机器本地生成一个，海况结构体放进 GameState 复制，时间来源接自己的网络时钟。
  3. 拷贝 SONetClock（或在已有的时钟同步里加上“最短往返样本 + 限速修正”），所有共享表现（海面、风暴、天气循环）都读它。
  4. 船：服务器固定步长模拟 + 自定义快照（WithNetSerializer、WithIdentical），客户端缓冲插值。先用整体插值跑通，再加竖直重建。
  5. 甲板角色直接用 CharacterMovement 的基座移动，不需要额外的网络代码。
  6. 渲染：已有海面材质的项目只需把位移来源换成这几张级联纹理并按静止位置采样；没有的可以拷贝 OceanSurface 与 Tools/build_assets.py 里的材质 HLSL。
  7. 用“两端吃水差”做回归测试：改了时钟、海面或呈现方式之后，跑一遍 -Net 自测看它有没有变大。
